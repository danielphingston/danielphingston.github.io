Stuck at max: why Hyper-V Dynamic Memory won't let go of Linux RAM

My Linux VM asked Hyper-V for 20.9 GB. It was using 4.

Hyper-V Dynamic Memory was switched on for our Ubuntu dev VM, and it still held all 12 GB around the clock. The cause is a single figure the Linux balloon driver sends to the host once a second. A small kernel module changes that figure, and the VM now settles near 6.8 GB with room to grow back to 12 GB when it needs to.

Daniel Phingston 6 November 2026 Ubuntu 22.04 · kernel 6.8.0-1063-azure · Windows 11 Hyper-V

The symptom

A 12 GB VM using about 4 GB

The laptop has 31.5 GB of RAM, and Task Manager sat at 86% in use. Inside the VM, htop showed 4.16 GB used out of 11.7 GB, with most of the rest held as page cache. Hyper-V had all 12 GB assigned, marked the VM's memory status as Warning, and reported a demand of 20.9 GB.

That demand figure was the clue. The VM was using about 4 GB, and Hyper-V believed it needed 20.9 GB, well above its 12 GB maximum.

Root cause

The guest reports reserved memory as demand

Hyper-V sizes a Dynamic Memory VM from a status report the guest sends every second. Windows guests fill that report with their commit charge, which tracks memory in use closely. The Linux driver, hv_balloon, was written in 2012 to speak the same protocol, and it fills the committed field from Committed_AS.

Committed_AS counts address space that processes have reserved. Databases, Go services, the JVM, Node and Docker all reserve far more than they touch. On this VM, ClickHouse alone accounted for about 6.4 GB of the reservation.

/* drivers/hv/hv_balloon.c: the figure sent to Hyper-V as "committed" */
static unsigned long get_pages_committed(struct hv_dynmem_device *dm)
{
	return vm_memory_committed() +          /* Committed_AS: 20.1 GB here */
		dm->num_pages_ballooned +
		(dm->num_pages_added > dm->num_pages_onlined ?
		 dm->num_pages_added - dm->num_pages_onlined : 0) +
		compute_balloon_floor();            /* about 0.8 GB at 12 GB */
}

Mainline Linux still uses this formula. Upgrading Ubuntu or the kernel leaves the behaviour unchanged.

With demand permanently above the 12 GB maximum, Hyper-V never sees spare memory in the VM, so it never asks the balloon driver to give any back.

The fix

Swap one term in the status report

hv_demand is a kernel module of about 100 lines. It leaves hv_balloon in place and uses kretprobes to change the value of a single function call, at the moment the driver builds its report. Use the toggle to compare the two reports.

Stock driver: demand sits above the maximum, so Hyper-V keeps the VM at 12 GB.

  1. A kretprobe on post_status() records which task is building the report, and clears the record when the function returns.
  2. A kretprobe on vm_memory_committed() checks the calling task. For calls from post_status(), it replaces the return value with MemTotal − MemAvailable + cushion_mb.
  3. The driver adds ballooned pages and its floor as usual, then sends the report. Hyper-V sees about 5.8 GB of demand and starts to reclaim.
static int vmc_return(struct kretprobe_instance *ri, struct pt_regs *regs)
{
	long total, avail, used;

	if (!READ_ONCE(enabled) || READ_ONCE(ps_task) != current)
		return 0;                      /* every other caller keeps Committed_AS */

	total = (long)totalram_pages();
	avail = si_mem_available();
	used = total - avail;
	if (used < 0)
		used = 0;
	used += (long)READ_ONCE(cushion_mb) << (20 - PAGE_SHIFT);

	regs_set_return_value(regs, (unsigned long)used);
	return 0;
}

/proc/meminfo and the kernel's overcommit checks still read the real Committed_AS. Running rmmod hv_demand restores the stock report immediately.

Results

12 GB down to 6.8 GB in about five minutes

The module was loaded on the running VM after a Standard checkpoint. Hyper-V picked up the new demand within a second, waited a few minutes, then inflated the balloon in two steps. Assigned memory has tracked demand plus the 20% buffer since then.

Growth test

Hyper-V gives the memory back when the VM needs it

Shrinking is half the job. To check the other direction, a test process in the guest took 4 GB in 256 MB steps, held it for a minute, then let go. A side effect

The swap feedback loop

Before the growth test, the guest already had 2.2 GB in swap. An hour later it was down to 5.5 GB of RAM with 2.6 GB in swap, spread across idle services: a Node build server, LocalStack, ClickHouse, DynamoDB Local and the VS Code server. The first version of the module caused this.

Hyper-V squeezesThe balloon inflates toward demand plus the 20% buffer, and the guest has to free memory to make room.
Linux swaps idle memoryOnce the page cache is thin, the kernel moves idle process memory out to swap.
Reported use dropsSwapped pages no longer count in MemTotal − MemAvailable, so demand falls and Hyper-V squeezes again.

The fix is an option, count_swap, that adds swap in use to the reported figure. Memory pushed out to swap still counts as demand, so Hyper-V stops shrinking the VM once it starts swapping. Modules cannot read total_swap_pages, so the install script passes SwapTotal from /proc/meminfo when it loads the module, and the module reads free swap from the exported nr_swap_pages.

	if (READ_ONCE(count_swap)) {
		long swap_used = (long)(READ_ONCE(swap_total_kb) >> (PAGE_SHIFT - 10)) -
				 atomic_long_read(&nr_swap_pages);
		if (swap_used > 0)
			used += swap_used;
	}

Turning it on raised the demand Hyper-V saw from about 4.7 GB to 6.9 GB within seconds, matching the swap in use. The VM now settles near 8.2 GB, and the swapped memory returns to RAM as the services touch it again.

Startup

Startup still gets the full 12 GB

Our services need the full 12 GB while they start, so the module loads late. The VM boots with 4 GB of startup memory and a 12 GB maximum. Before the module loads, the stock driver reports the high Committed_AS figure, so Hyper-V hot-adds memory up to 12 GB within seconds. A systemd timer loads the module 10 minutes after boot, and the VM then shrinks to what it uses.

Before you start

What the VM needs

The script checks each of these and stops with a message if one is missing.

  • Dynamic Memory on, startup below maximum. With startup equal to the maximum, Hyper-V has no room to shrink the VM.
  • The hv_balloon driver loaded. It ships with Ubuntu's linux-azure and generic kernels, and loads on its own in a Hyper-V VM.
  • Secure Boot off for the VM. The module is unsigned, and kernel lockdown blocks unsigned modules.
  • A compiler and kernel headers. The script installs build-essential and linux-headers-$(uname -r) with apt-get if they are missing, so it needs network access the first time.
  • A checkpoint first. Take a Standard checkpoint in Hyper-V Manager before loading a kernel module on a VM you care about.
Using it

One script per VM

hyperv-memory-reclaim.sh carries the module source. It checks the platform, installs the compiler and headers if they are missing, builds for the running kernel, loads the module and adds the boot timer. After a kernel update, the next boot rebuilds it automatically. Re-running it with new options applies them to the loaded module, and reloads the module if the build has changed.

sudo ./hyperv-memory-reclaim.shBuild, load now and load again 10 minutes after every boot
sudo hyperv-memory-reclaim install --count-swapCount swap in use as demand, so Hyper-V stops squeezing idle memory out to swap
sudo hyperv-memory-reclaim install --delay 15 --cushion 2048Change the boot delay or the headroom kept for page cache
sudo hyperv-memory-reclaim statusModule state, boot timer and memory returned to Hyper-V
sudo hyperv-memory-reclaim unloadReturn to the stock driver now; the boot timer stays
sudo hyperv-memory-reclaim uninstallRemove the module, the timer and every installed file

On the host, keep the VM's startup memory below its maximum. With startup equal to the maximum, Hyper-V has no room to shrink the VM.

The script only adds files. It edits no existing file, and the hv_balloon driver on disk is never touched. Under the hood

How insmod loads the module, and how the probes fire

A kernel module is compiled code that the running kernel links into itself, with the same access as the rest of the kernel. insmod is the smallest tool for loading one. Use the toggle to step through the load, then through a single status report once the probes are in place.

user space

1. insmod opens the file

insmod takes a path to a .ko file, opens it and hands the open file and the option string to the kernel in one system call, finit_module(). That is all it does in user space.

Unlike modprobe, it does not look in /lib/modules, read /etc/modprobe.d or load dependencies. Nothing about hv_demand is registered with the system, so it never loads on its own: only the script and its boot timer load it.

insmod /opt/hv-demand/build/$(uname -r)/hv_demand.ko \
       cushion_mb=1024 count_swap=0 swap_total_kb=4194300
# becomes, roughly:
finit_module(fd, "cushion_mb=1024 count_swap=0 swap_total_kb=4194300", 0);
kernel

2. The kernel decides whether to allow it

The caller needs CAP_SYS_MODULE, which in practice means root, and kernel.modules_disabled must be 0. Then the kernel looks for a signature. With lockdown on, which Secure Boot usually switches on, an unsigned module is refused outright. That is why the script checks lockdown first and asks for Secure Boot to be off.

Without lockdown, the kernel accepts the module and marks itself tainted: O for out-of-tree and E for unsigned. The taint is a label for bug reports, and changes nothing about how the kernel runs.

kernel

3. The build must match the running kernel

Every .ko carries a vermagic string recording the exact kernel it was built against, along with symbol version checksums. If they do not match the running kernel, the load fails with Invalid module format.

So a module built for 6.8.0-1063-azure will not load on the next kernel update. The script keeps one build folder per kernel version and builds a new one the first time it sees a new kernel.

$ modinfo -F vermagic hv_demand.ko
6.8.0-1063-azure SMP preempt mod_unload modversions
kernel

4. The kernel links the code into itself

The kernel allocates memory for the module, copies in its code and data, and fills in every function and variable it calls from the rest of the kernel. A module can only use symbols the kernel exports.

register_kretprobe, si_mem_available and nr_swap_pages are exported. total_swap_pages is not, which is why the script reads SwapTotal from /proc/meminfo and passes it in as a parameter.

kernel

5. Options become parameters in /sys

The kernel parses the option string into the module's variables, then creates a file for each one under /sys/module/hv_demand/parameters/. They were declared with mode 0644, so root can change them while the module runs.

That is how re-running the script with new options applies them instantly, without unloading anything.

echo 2048 | sudo tee /sys/module/hv_demand/parameters/cushion_mb
echo 0    | sudo tee /sys/module/hv_demand/parameters/enabled   # back to the stock figure
kernel

6. init registers the two probes

Finally the kernel calls the module's init function, hv_demand_init(). It registers a kretprobe on vm_memory_committed(), then one on post_status(), and writes a line to the kernel log. If either registration fails, init returns the error, the kernel throws the module away and insmod prints the error.

From the next status report on, Hyper-V sees the new figure.

$ sudo dmesg | grep hv_demand
hv_demand: reporting MemTotal-MemAvailable+1024MB to Hyper-V
hv_balloon

1. post_status() starts, and the entry probe notes who called it

Once a second, hv_balloon calls post_status() to build its report. A kprobe sits on the function's first instruction: the kernel swapped it for a breakpoint, or uses the ftrace hook at the start of the function where there is one. When it fires, ps_entry() runs and records the current task in ps_task.

Because this is a return probe, the kernel also swaps the function's return address for one that leads to a small piece of kernel code called a trampoline.

mm

2. vm_memory_committed() runs untouched

Inside get_pages_committed(), the driver calls vm_memory_committed(), which returns Committed_AS: 20.1 GB on this VM. The function itself is never changed. Its return address has been swapped too, by the second kretprobe.

hv_demand

3. The return trampoline replaces the value

Instead of going straight back to its caller, the function returns into the trampoline, which calls vmc_return() with a copy of the CPU registers. The return value is in one of them (rax on x86).

If the task matches ps_task, the handler overwrites that register with real use plus the cushion, using regs_set_return_value(). Then the trampoline jumps back to the real caller, which sees the new value.

hv_balloon

4. The report goes to the host as usual

get_pages_committed() adds the ballooned pages and the balloon floor as it always does, and post_status() sends DM_STATUS_REPORT to Hyper-V over VMBus. The driver has no idea anything changed.

hv_demand

5. The exit probe clears the marker

When post_status() returns, its own trampoline runs ps_return(), which clears ps_task. Any other call to vm_memory_committed() now gets the real figure.

That includes /proc/meminfo, which calls the same function. When you run cat /proc/meminfo, the calling task is cat, not the balloon worker, so Committed_AS reads true.

Unloading. rmmod hv_demand calls delete_module(). The kernel runs hv_demand_exit(), which unregisters both probes and waits for any handler still running. The original instructions and return paths are restored, and the module's memory is freed. The next report, at most a second later, carries Committed_AS again. The taint flag stays until the next reboot.

Trade-offs

What to know before you run it

Smaller page cache

Hyper-V reclaims cache along with idle memory. Databases read more from disk until the cache warms up again. Raise cushion_mb to keep more of it.

Fast spikes

A program that suddenly touches memory it reserved long ago has to wait for Hyper-V to add memory back. In testing that took about 5 seconds to start, and the 4 GB swap file absorbed the gap.

Tainted kernel

The module is unsigned and built out of tree, so the kernel log marks it as tainted. It also needs Secure Boot off for the VM.

Upstream path

Changing the default for every Linux guest on Hyper-V would cause regressions for other workloads. An opt-in hv_balloon parameter is a realistic patch for linux-hyperv@vger.kernel.org, with this data as evidence.

# Run inside a Hyper-V VM: let Hyper-V Dynamic Memory take back RAM the VM isn't using.
#
# The Linux Hyper-V balloon driver reports Committed_AS (reserved address space) as the VM's memory demand.
# With our service stack that is ~20GB while ~4GB is actually used, so Hyper-V never shrinks the VM.
# This builds and loads a small kernel module (hv_demand) that reports real use instead
# (MemTotal - MemAvailable + a cushion). Only the figure sent to Hyper-V changes; /proc/meminfo and
# overcommit are untouched. Hyper-V then reclaims spare memory after a few minutes and gives it back
# (up to the VM's maximum) when the VM needs it.
#
# Needs Dynamic Memory on the VM with startup below maximum (if startup = maximum, Hyper-V never shrinks it).
#
# Usage: sudo ./hyperv-memory-reclaim.sh [command] [options]
#   install        (default) build, load now, and load again on every boot after a delay
#     --no-boot      load now only; don't add the boot timer
#     --no-load      build and add the boot timer; don't load now
#     --cushion MB   MB reported on top of real use (default 1024; higher keeps more page cache)
#     --delay MIN    minutes after boot before loading (default 10, so startup gets the full maximum)

// SPDX-License-Identifier: GPL-2.0
/*
 * hv_demand - make the Hyper-V balloon driver report real memory use as demand.
 *
 * hv_balloon's post_status() tells the host how much memory the guest needs using
 * vm_memory_committed() (Committed_AS). On Linux that is reserved address space, which
 * for ClickHouse/Go/JVM/Node workloads is far above what is actually used, so Hyper-V
 * Dynamic Memory never takes memory back.
 *
 * This module swaps the Committed_AS term, only when called from post_status(), for
 * (MemTotal - MemAvailable + cushion_mb). The driver still adds ballooned pages,
 * not-yet-onlined hot-added pages and its balloon floor on top, as before.
 * Nothing else that reads Committed_AS (/proc/meminfo, overcommit) is affected.
 *
 * Runtime knobs (/sys/module/hv_demand/parameters/):
 *   enabled        1 = report real use, 0 = pass through the original value
 *   cushion_mb     extra MB added to the reported use (headroom for page cache)
 *   count_swap     1 = also report swap in use, so memory pushed out to swap still counts
 *                  as demand and Hyper-V stops squeezing once the guest starts swapping
 *   swap_total_kb  SwapTotal from /proc/meminfo (total_swap_pages isn't exported to modules)
 * rmmod restores the stock behaviour.
 */
#include <linux/module.h>
#include <linux/kprobes.h>
#include <linux/mm.h>
#include <linux/sched.h>
#include <linux/swap.h>
#include <linux/atomic.h>

static int enabled = 1;
module_param(enabled, int, 0644);
MODULE_PARM_DESC(enabled, "1 = report real memory use to Hyper-V, 0 = original Committed_AS");

static unsigned int cushion_mb = 1024;
module_param(cushion_mb, uint, 0644);
MODULE_PARM_DESC(cushion_mb, "MB added to the reported use (default 1024)");

static int count_swap;
module_param(count_swap, int, 0644);
MODULE_PARM_DESC(count_swap, "1 = also report swap in use as demand (needs swap_total_kb)");

static unsigned long swap_total_kb;
module_param(swap_total_kb, ulong, 0644);
MODULE_PARM_DESC(swap_total_kb, "SwapTotal in kB from /proc/meminfo, set by the install script");

/* Task currently inside post_status(), or NULL. */
static struct task_struct *ps_task;

static int ps_entry(struct kretprobe_instance *ri, struct pt_regs *regs)
{
	cmpxchg(&ps_task, NULL, current);
	return 0;
}

static int ps_return(struct kretprobe_instance *ri, struct pt_regs *regs)
{
	cmpxchg(&ps_task, current, NULL);
	return 0;
}

static int vmc_return(struct kretprobe_instance *ri, struct pt_regs *regs)
{
	long total, avail, used;

	if (!READ_ONCE(enabled) || READ_ONCE(ps_task) != current)
		return 0;

	total = (long)totalram_pages();
	avail = si_mem_available();
	used = total - avail;
	if (used < 0)
		used = 0;
	used += (long)READ_ONCE(cushion_mb) << (20 - PAGE_SHIFT);

	if (READ_ONCE(count_swap)) {
		long swap_used = (long)(READ_ONCE(swap_total_kb) >> (PAGE_SHIFT - 10)) -
				 atomic_long_read(&nr_swap_pages);
		if (swap_used > 0)
			used += swap_used;
	}

	regs_set_return_value(regs, (unsigned long)used);
	return 0;
}

static struct kretprobe ps_probe = {
	.kp.symbol_name = "post_status",
	.entry_handler  = ps_entry,
	.handler        = ps_return,
	.maxactive      = 8,
};

static struct kretprobe vmc_probe = {
	.kp.symbol_name = "vm_memory_committed",
	.handler        = vmc_return,
	.maxactive      = 64,
};

static int __init hv_demand_init(void)
{
	int ret;

	ret = register_kretprobe(&vmc_probe);
	if (ret) {
		pr_err("hv_demand: probe on vm_memory_committed failed: %d\n", ret);
		return ret;
	}
	ret = register_kretprobe(&ps_probe);
	if (ret) {
		pr_err("hv_demand: probe on post_status failed: %d\n", ret);
		unregister_kretprobe(&vmc_probe);
		return ret;
	}
	pr_info("hv_demand: reporting MemTotal-MemAvailable+%uMB%s to Hyper-V\n", cushion_mb,
		count_swap ? "+swap used" : "");
	return 0;
}

static void __exit hv_demand_exit(void)
{
	unregister_kretprobe(&ps_probe);
	unregister_kretprobe(&vmc_probe);
	pr_info("hv_demand: unloaded, missed ps=%d vmc=%d\n", ps_probe.nmissed, vmc_probe.nmissed);
}

module_init(hv_demand_init);
module_exit(hv_demand_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Report real memory use (not Committed_AS) to Hyper-V Dynamic Memory");
EOF
    put_file "${SRC_DIR}/hv_demand.c"
}

ensure_toolchain() {
    local kver="$1" pkgs=()
    command -v make >/dev/null && command -v gcc >/dev/null || pkgs+=(build-essential)
    [ -d "/lib/modules/${kver}/build" ] || pkgs+=("linux-headers-${kver}")
    [ ${#pkgs[@]} -eq 0 ] && return 0
    command -v apt-get >/dev/null || die "Missing ${pkgs[*]} and no apt-get to install them."
    info "Installing ${pkgs[*]}..."
    DEBIAN_FRONTEND=noninteractive apt-get install -y -q "${pkgs[@]}" \
        || die "Couldn't install ${pkgs[*]}. Install them, then run: $SELF load"
}

# Builds once per kernel version, so a kernel update gets a fresh build on the next load.
build_module() {
    local kver out
    kver="$(uname -r)"
    out="${BUILD_ROOT}/${kver}"
    if [ -f "${out}/${MODULE}.ko" ] && [ "${out}/${MODULE}.ko" -nt "${SRC_DIR}/hv_demand.c" ]; then
        return 0
    fi
    ensure_toolchain "$kver"
    info "Building ${MODULE} for ${kver}..."
    rm -rf "$out"
    mkdir -p "$out"
    cp "${SRC_DIR}/Makefile" "${SRC_DIR}/hv_demand.c" "$out/"
    make -s -C "/lib/modules/${kver}/build" M="$out" modules >"${out}/build.log" 2>&1 \
        || { cat "${out}/build.log" >&2; die "Build failed (log: ${out}/build.log)"; }
}

# ---------------------------------------------------------------------------------------------------------
# Load / unload

describe() {
    local swap="real use only"
    [ "$COUNT_SWAP" = "1" ] && swap="swap in use counted"
    echo "cushion ${CUSHION_MB} MB, ${swap}"
}

load_module() {
    local ko
    build_module
    ko="${BUILD_ROOT}/$(uname -r)/${MODULE}.ko"
    if is_loaded; then
        if [ "$(modinfo -F srcversion "$ko")" = "$(cat "/sys/module/${MODULE}/srcversion" 2>/dev/null)" ]; then
            echo "$CUSHION_MB" > "/sys/module/${MODULE}/parameters/cushion_mb"
            swap_total_kb > "/sys/module/${MODULE}/parameters/swap_total_kb"
            echo "$COUNT_SWAP" > "/sys/module/${MODULE}/parameters/count_swap"
            echo 1 > "/sys/module/${MODULE}/parameters/enabled"
            info "${MODULE} already loaded; settings applied ($(describe))."
            return 0
        fi
        info "Loaded ${MODULE} is an older build; reloading it."
        rmmod "$MODULE"
    fi
    insmod "$ko" cushion_mb="$CUSHION_MB" count_swap="$COUNT_SWAP" swap_total_kb="$(swap_total_kb)"
    info "${MODULE} loaded ($(describe)). Hyper-V usually starts reclaiming within ~5 minutes."
}

unload_module() {
    if is_loaded; then
        rmmod "$MODULE"
        info "${MODULE} unloaded; Hyper-V sees Committed_AS again."
    else
        echo "${MODULE} isn't loaded."
    fi
}

# ---------------------------------------------------------------------------------------------------------
# Boot timer

install_boot() {
    cat > "/etc/systemd/system/${UNIT}.service" <<EOF
[Unit]
Description=Report real memory use to Hyper-V Dynamic Memory (${MODULE})

[Service]
Type=oneshot
ExecStart=${SELF} load
EOF
    cat > "/etc/systemd/system/${UNIT}.timer" <<EOF
[Unit]
Description=Load ${MODULE} ${BOOT_DELAY_MIN} min after boot, once startup has had the full memory maximum

[Timer]
OnBootSec=${BOOT_DELAY_MIN}min
AccuracySec=30s

[Install]
WantedBy=timers.target
EOF
    systemctl daemon-reload
    # enable without --now: starting a timer whose OnBootSec has passed would fire it immediately
    systemctl enable "${UNIT}.timer" >/dev/null 2>&1
    info "Boot timer enabled: loads ${MODULE} ${BOOT_DELAY_MIN} min after each boot."
}

remove_boot() {
    systemctl disable --now "${UNIT}.timer" >/dev/null 2>&1 || true
    rm -f "/etc/systemd/system/${UNIT}.service" "/etc/systemd/system/${UNIT}.timer"
    systemctl daemon-reload
}

# ---------------------------------------------------------------------------------------------------------
# Commands

cmd_install() {
    local boot=1 load=1
    while [ $# -gt 0 ]; do
        case "$1" in
            --no-boot) boot=0 ;;
            --no-load) load=0 ;;
            --cushion) shift; [[ "$1" =~ ^[0-9]+$ ]] || die "--cushion needs a number of MB"; CUSHION_MB="$1" ;;
            --delay)   shift; [[ "$1" =~ ^[0-9]+$ ]] || die "--delay needs a number of minutes"; BOOT_DELAY_MIN="$1" ;;
            --count-swap)    COUNT_SWAP=1 ;;
            --no-count-swap) COUNT_SWAP=0 ;;
            *) usage ;;
        esac
        shift
    done

    check_platform
    # keep an installed copy so the boot timer works even if this file moves
    if [ "$(readlink -f "$0")" != "$SELF" ]; then
        install -m 755 "$0" "$SELF"
    fi
    save_conf
    write_source
    build_module
    [ "$load" -eq 1 ] && load_module
    if [ "$boot" -eq 1 ]; then
        install_boot
    else
        remove_boot
        warn "No boot timer: ${MODULE} won't be loaded after a restart."
    fi
    echo "Check progress with: $SELF status"
}

cmd_status() {
    local kver
    kver="$(uname -r)"
    echo "Kernel:        ${kver}"
    if is_loaded; then
        local p="/sys/module/${MODULE}/parameters"
        echo -e "Module:        ${GREEN}loaded${NC} (enabled=$(cat $p/enabled)," \
            "cushion=$(cat $p/cushion_mb) MB, count_swap=$(cat $p/count_swap 2>/dev/null || echo n/a))"
    else
        echo -e "Module:        ${YELLOW}not loaded${NC}"
    fi
    if [ -f "${BUILD_ROOT}/${kver}/${MODULE}.ko" ]; then
        echo "Built:         yes, for this kernel"
    else
        echo "Built:         no, for this kernel (built on next load)"
    fi
    if systemctl is-enabled "${UNIT}.timer" >/dev/null 2>&1; then
        echo "Boot timer:    enabled, ${BOOT_DELAY_MIN} min after boot" \
            "(last run: $(systemctl show -p LastTriggerUSec --value "${UNIT}.timer"), result: $(systemctl show -p Result --value "${UNIT}.service"))"
    else
        echo "Boot timer:    not enabled"
    fi
    if [ -r /sys/kernel/debug/hv-balloon ]; then
        local ballooned
        ballooned=$(awk -F: '/pages_ballooned/ {gsub(/ /,"",$2); print $2}' /sys/kernel/debug/hv-balloon)
        echo "Given back:    $(( ballooned * 4 / 1024 )) MB returned to Hyper-V (balloon)"
    fi
    echo
    free -m | head -2
}

cmd_uninstall() {
    unload_module
    remove_boot
    rm -rf "$INSTALL_DIR" "$CONF" "$SELF"
    info "Removed. Hyper-V sees Committed_AS again."
}

COMMAND="${1:-install}"
[ $# -gt 0 ] && shift

case "$COMMAND" in
    install)    require_root; cmd_install "$@" ;;
    status)     require_root; cmd_status ;;
    load)       require_root; check_platform; [ -f "${SRC_DIR}/hv_demand.c" ] || write_source; load_module ;;
    unload)     require_root; unload_module ;;
    uninstall)  require_root; cmd_uninstall ;;
    --no-boot|--no-load|--cushion|--delay|--count-swap|--no-count-swap) require_root; cmd_install "$COMMAND" "$@" ;;
    -h|--help|help) usage ;;
    *) usage ;;
esac
